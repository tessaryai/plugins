# tessary plugin — changelog

> **TL;DR (v0.2.0, current — adds `/connect`: registers a self-hosted instance's read-only MCP tools into Claude Code, with a `platform.py` helper that never lets the agent see the admin token.)**
> There's no OAuth for a self-hosted, open-edition instance — the credential is an admin-scoped project API key (`tsy_a_...`) a human mints once under Settings → MCP tokens and pastes into a hidden prompt. `platform.py link` stores it under `~/.config/tessary/credentials.json` (`chmod 600`, keyed by repo root); `platform.py status` verifies it against the instance's `/mcp` endpoint before anything is registered; `platform.py mcp-add --run` runs `claude mcp add --transport http --scope local tessary <origin>/mcp --header "Authorization: Bearer <token>"` from the script itself — never a command the agent constructs or prints with the real value (the no-`--run` form shows a masked preview only). `platform.py unlink` tears down both the local MCP registration and the stored credential together. Verified against a real local instance: `link` + `status` + `mcp-add --run` all round-tripped against a throwaway project, `claude mcp list` showed the server connected, and `unlink` removed both pieces cleanly. If you pin the marketplace `ref`, use `tessary-v0.2.0`.

> **TL;DR (v0.1.0 — initial skeleton: `/setup` and `/instrument`, both thin pointers at the canonical workflows in `tessaryai/tessary`'s repo root. No `/connect` yet.)**
> This is the first release of the `tessary` plugin, replacing nothing (it is not a rename or migration of `evals` — see that plugin's own changelog for its deprecation notice). It ships two skills: `/setup` installs and starts a local Tessary instance; `/instrument` tags a repo's model-call spans with `tessary.call_site.id` and wires OTLP export. Both bodies are a single line pointing at `setup.md` / `instrument.md` at the root of `tessaryai/tessary`, so the workflow has one source of truth regardless of whether a user pastes the raw GitHub URL or runs the slash command. `/tessary:connect` (registering Tessary's read-only MCP tools into the session, keyed on a project's admin-scoped API key) is not part of this release; it lands in a follow-up version once its credential-handling helper is built. If you pin the marketplace `ref`, use `tessary-v0.1.0`.
