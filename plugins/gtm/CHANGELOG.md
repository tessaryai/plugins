# gtm plugin — changelog

> **TL;DR (v0.1.0, current — initial release: a Notion-hosted CRM and seven go-to-market skills, `/gtm:setup`, `/gtm:import`, `/gtm:sweep`, `/gtm:campaign-build`, `/gtm:campaign-write`, `/gtm:campaign-run` and `/gtm:funnel`. The helper scripts are tested; no live end-to-end run against a real Notion workspace or connector has been done yet.)**
> `/gtm:setup` creates five Notion databases (Contacts, Companies, Pipeline, Campaigns, Meetings) and a Funnel page from `templates/schema.json`, or maps an existing set through `notion.field_map`, `notion.status_map` and `notion.option_map`, and writes `~/.config/gtm/config.json`. Every skill works with only the Notion connector; a Notion integration token, when saved, moves bulk work to `lib/notion_rest.py`. `/gtm:import` reads a CSV or Google Sheets export, HubSpot, Pipedrive or Attio read-only, dedupes by email, LinkedIn URL and company domain, and writes only after a preview and a yes. `/gtm:sweep` mirrors email, calendar, LinkedIn (Claude in Chrome), meeting recorders and outreach tools into the CRM with forward-only Status changes and dated log lines. `/gtm:campaign-build` sources and scores an audience from the ICP with the enrichment adapters; `/gtm:campaign-write` writes the sequence and per-contact copy in the user's voice and leaves the campaign at Review; `/gtm:campaign-run` sends only for Active campaigns, only text found word for word on the pages, with every gate (Do Not Contact, reply stop, working days and send window, daily caps, verify before marker). It defaults to live mode, with a LinkedIn invite cap of 10 a day and a plain account-risk warning in setup; `sending.mode` = `dry-run` or a `dry-run` argument sends nothing. `/gtm:funnel` counts with `lib/funnel.py` and publishes only when its checks pass. Adapters in v1: email (gmail, outlook), calendar (google, outlook), linkedin (chrome), meetings (fathom, granola, fireflies, otter), outreach (gojiberry, lemlist, instantly, apollo), enrichment (exa, apollo, hunter, mcp), notify (push, slack), import (csv, hubspot, pipedrive, attio). Secrets live only in `~/.config/gtm/credentials.json` (`chmod 600`), saved with `config.py set-secret` at a hidden prompt; the API client `lib/readonly_api.py` is GET-only with a fixed path allowlist. Verified: `--help` of every `lib/` script on the default `python3` and on Python 3.9, the `funnel.py self-test`, and scratch smoke tests of `notion_rest.py` (bad id and fake token give clean exit codes and never print the token), `readonly_api.py` (missing key, path off the allowlist), `csv_import.py suggest` and `plan`, and `config.py` (`set`, `get`, `state-set`, secret refusal, masking in `show`). Not verified: any run against a live Notion workspace or a live connector (the MCP insert round trip for headings and code blocks, MCP query row shapes for the funnel export, the import per-row lookup path), any real send, and the vendor field names, paging and UI paths in the HubSpot, Pipedrive, Attio, lemlist, Instantly, Apollo, Hunter, Fireflies, Granola, Otter, Fathom and Outlook adapters; each adapter tells the agent that the live schema wins. Known limits: LinkedIn people search is not in v1; Apollo (outreach and enrichment) needs the Apollo connector; Attio import without its connector goes through a CSV export. If you pin the marketplace `ref`, use `gtm-v0.1.0`.
